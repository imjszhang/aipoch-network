## 1. 产品是什么

AIPOCH Network 是一个尽可能复用 GitHub 的独立科研目录。它帮助用户发现研究项目、可复用能力及相关组织和研究者，查看来源、版本、条件与关系，再到原项目协作，或在 Open-Science 工作台继续研究。

- **Network** 负责科研发现、目录表达、对象选择、引用审阅、工作台连接反馈和接续反馈。
- **Open-Science** 是工作台入口与使用场所。**未来 AIPOCH Connector** 负责工作台一侧的 GitHub 授权、仓库访问、导入、同步及需要权限的操作。
- **GitHub 原项目** 继续保存代码、文档、版本和原有协作。收录不要求迁移仓库、加入指定组织或改造原项目。
- **目录仓库** 接受收录建议与更正，维护目录规则和公开契约。它与被收录的原项目仓库不同。

默认路径是 **先浏览和选择，再按需要连接工作台**。连接带来后续操作，不能成为浏览、搜索、阅读来源或准备公开推荐的门槛。

## 2. 固定要求：不得在适配中丢失

| ID | 要求 | 必须保持的结果 |
| --- | --- | --- |
| R01 | 复用已有 GitHub 项目与组织 | 一个公开 URL 即可开始推荐；不要求专用 manifest、Topics、客户端安装或 AIPOCH 账号。组织链接不自动收录整个组织。 <!-- 设计依据：S-DR-173, S-DR-174, S-DR-176 --> |
| R02 | Network 独立可用 | 网站采用既有静态目录与 GitHub Pages 方向，无自建常驻后端；构建、测试、运行和发布不依赖 Open-Science 源码、在线状态或版本。 <!-- 设计依据：S-DR-173, S-DR-174, S-DR-176 --> |
| R03 | 网页不处理 GitHub 授权 | 没有 GitHub 登录、账号绑定、token、scope、权限诊断或身份修复表面；这些由未来 Connector 处理。 <!-- 设计依据：S-DR-175, S-DR-176 --> |
| R04 | 顶栏右侧仅一个 Open-Science 入口 | 名称保持 `Open-Science`，状态随连接变化；没有 My Network、独立 Saved 或右侧 Contribute。移动端同样如此。 <!-- 设计依据：S-DR-175, S-DR-176 --> |
| R05 | 未连接和已连接有实际区别 | 首页和项目/能力按钮随状态变化，连接操作从正常浏览路径可达，不能只在 Review 场景中出现。 <!-- 设计依据：S-DR-175, S-DR-176 --> |
| R06 | 原对象续接 | 选中对象 → 连接 → 恢复同一对象审阅 → 明确确认 → 发送 → 匹配回执；不跳首页、不换对象、不自动发送。 <!-- 设计依据：S-DR-175, S-DR-176 --> |
| R07 | 连接、收到引用、执行分别表达 | Connected 不代表已收到引用；Received 不代表 clone、导入、安装、执行或科学验证成功。 <!-- 设计依据：S-DR-175, S-DR-176 --> |
| R08 | 旧确认不能复用 | 改对象、动作、来源、版本、许可、条件或有效会话后重新审阅；取消、超时、断开、替换后的旧响应不能恢复成功。 <!-- 设计依据：S-DR-175, S-DR-176 --> |
| R09 | 收藏与上下文属于浏览器 | 仅已连接可访问 Saved/Recently viewed 和收藏操作；未连接隐藏入口并阻止修改；断开保留浏览位置、筛选、选择和收藏，不暗示云同步。 <!-- 设计依据：S-DR-175, S-DR-176 --> |
| R10 | 目录状态与用户连接无关 | 收录、维护者认可、组织官方确认、科研验证分别表达；不因工作台连接变绿而升级目录声明。 <!-- 设计依据：S-DR-175, S-DR-176 --> |
| R11 | 保留指定视觉和品牌 | 沿用本 HTML 的黑白黄、网格、衬线主标题、项目行/能力卡及 Open-Science 产品卡；使用圆环＋中心点＋三条交叉线 logo。 <!-- 设计依据：S-DR-173, S-DR-174, S-DR-176 --> |
| R12 | 数据和反馈真实可解释 | 示例、未知许可、未固定版本、陈旧、缺失、撤回等有明确表达；打开外链、时间经过和本地 toast 不充当操作成功证据。 <!-- 设计依据：S-DR-173, S-DR-174, S-DR-176 --> |

公开主体资料可以出现 GitHub 用户名、组织名和公开参与证据；这属于目录内容，不是访问者的授权状态。不得为了删除登录逻辑而删掉正常的来源和主体资料。

## 3. 页面、入口与信息层级

### 3.1 全局结构

桌面主导航保留 `Explore / Projects / Capabilities / Organizations / Community`，品牌链接回首页。Researchers、Collections、Sources 可通过 Explore 分类、内容关系及二级入口访问。移动端可折叠浏览导航，但仍保留同一个 Open-Science 控件；导航菜单按钮不算第二个个人/工作台入口。

未连接时，右上角浮窗显示 `Connect Open-Science`。连接成功说明工作台已在运行；全站不得提供独立打开客户端的按钮或模拟打开客户端的反馈页。已连接首页切换为个人研究区，Join 显示连接状态，浮窗保留断开、回个人首页和具体对象接续；项目/能力操作继续保留。<!-- 设计依据：S-DR-179 -->

右上角浮窗只负责连接：未连接显示简短说明、状态、Connect Open-Science / Get Open-Science；已连接显示状态、Your research home、Disconnect。有待接续对象时加一行名称和 Continue。移除库标签页、收益介绍和嵌套卡片。Saved、Recently viewed、Reference receipts 集中在已连接个人首页，回执仍只表示收到引用。<!-- 设计依据：S-DR-185 -->

首页搜索框下方采用线上站点的五格目录样式：Projects、Capabilities、Organizations、Researchers、Collections；每格为分类名称、较大衬线数量及右上箭头，细边框连续分隔，悬停黄色。数量分别来自当前项目、能力、组织、研究者和集合目录的实际条目数，不用 01–05 序号或写死线上数量。手机为两列，最后一格通栏；数字保持可见，分类链接保持原目标。<!-- 设计依据：S-DR-180 -->

所有 `Get Open-Science` 入口统一指向 `https://aipoch.com/open-science`，用于了解和获取客户端；打开该页面不代表连接成功。<!-- 设计依据：S-DR-181 -->

已连接个人首页及 Join 中的状态提示采用小绿点、灰色 `Open-Science connected` 文字和更淡的小号 `Demo`；不用黄色背景、边框或按钮式强调。状态与 Demo 仍以文字可读，不只依赖颜色。<!-- 设计依据：S-DR-182 -->

连接后的首页沿用 v8 的个人研究布局：Welcome back、轻量连接状态、Explore / Share your research，以及 Your feed、Your projects、Saved、Following、Contributions。整体替换未连接宣传首页，含 hero 及下方主内容；断开立即恢复宣传首页，已有收藏仍保留。五格数量搜索区属于未连接发现首页。<!-- 设计依据：S-DR-184 -->

Your feed 在 Recently viewed / Reference receipts 间切换，并展示待接续对象，Saved 使用已保存目录条目；侧栏提供连接详情和跳转首页回执视图的入口。个人项目、关注、贡献尚无真实 Connector 数据时展示明确空状态，不用公共项目或虚构动态冒充用户内容。Share your research 进入现有公开推荐草稿，不假装发布成功；这是对旧版 Publish an asset 的真实范围适配。<!-- 设计依据：S-DR-184 -->

### 3.3 原型路由到实施路由

HTML 使用 hash 路由是单文件运行方式，不是生产 URL 契约。接收项目应沿用自己的静态路由、稳定 ID、历史重定向和 GitHub Pages 子路径规则。

| HTML 路由族 | 需要映射的页面 |
| --- | --- |
| `#/`、`#/explore` | 首页、综合发现 |
| `#/projects`、`#/projects/:id` | 项目目录及详情 |
| `#/capabilities`、`#/capabilities/:id` | 能力目录及详情 |
| `#/organizations`、`#/researchers`、`#/collections`、`#/sources` 及详情 | 公开主体、专题与来源页面 |
| `#/community`、`#/contribute`、`#/submit`、`#/join` | 社区、贡献说明、公开推荐、工作台参与 |
| `#/me` | 兼容收藏入口 |
| `#/review`、`?scenario=...`、示例与撤回路由 | 设计评审/异常状态参考，按演示边界处理 |

不得把原型的编码形式直接写入公开目录契约。站内链接、分享链接、来源链接应分别使用正确目标；深链接、刷新、返回、根域名和项目子路径均需验证。

## 5. 用户流程与状态语义

### 5.1 从具体内容开始

1. 用户在当前目录或详情选择项目/能力。保存稳定对象 ID、动作与返回上下文。 <!-- 设计依据：S-DR-175, S-DR-176 -->
2. 未连接时进入连接流程；正常浏览仍保持可用。已有连接时直接展示原对象引用审阅。 <!-- 设计依据：S-DR-175, S-DR-176 -->
3. 有效连接确认后恢复原对象，**只进入审阅，不自动发送**。 <!-- 设计依据：S-DR-175, S-DR-176 -->
4. 展示全部来源、完整版本、路径、许可、条件及目标工作台。用户确认当前准确内容后，才允许发送。 <!-- 设计依据：S-DR-175, S-DR-176 -->
5. 等待本次请求的匹配回执。收到后表达“引用已收到”；继续研究的后续步骤由工作台处理。 <!-- 设计依据：S-DR-175, S-DR-176 -->
6. 关闭/返回保留原页和筛选，尽量恢复滚动及触发控件焦点。失效对象明确说明并提供目录入口，不悄悄换成第一条数据。 <!-- 设计依据：S-DR-175, S-DR-176 -->

### 5.2 连接状态

| 状态 | 意义与允许动作 |
| --- | --- |
| Disconnected / Not connected | 尚无当前有效连接。可浏览、选择、连接、获取工作台。不能推断未安装。 |
| Connecting | 用户已发起一次新尝试，等待确认。允许取消；每次尝试有独立标识。 |
| Connected | 当前有效尝试已确认，产生有效会话。允许审阅、发送、断开。Demo 会话持续标示。 |
| Unconfirmed / Not confirmed | 无响应、取消等待或一般失败，未能确认连接。允许重试和继续浏览。 |
| Interrupted | 当前连接明确中断。禁止新发送，允许重连；不暗示研究任务已停止。 |

打开链接、应用窗口返回焦点、页面计时器结束，都不是生产连接成功依据。获取客户端下载链接也不代表网站检测到了安装状态。

### 5.3 引用与回执约束

引用状态可以使用接收项目自己的类型名，但必须表达：Selected、Reviewing、Ready、Sending、Received、Needs review、Cancelled、Unconfirmed/Failed、Continue in workbench。

- Ready 同时绑定当前有效会话和用户实际审阅的内容；取消勾选或内容/会话变化立即失效。
- Sending 期间不能重复发送同一请求。选择第二个对象时，要继续等待或明确替换，不能静默覆盖；普通“查看当前接续”不得使在途请求消失。
- 回执必须关联当前有效会话、本次请求、同一对象和准确的已审阅内容。关联方式由真实协议确定，但这些语义缺一不可。
- 停止等待、超时、断开、重试、替换或离开场景后，旧响应不得覆盖新对象、新增未经匹配的成功记录或恢复连接。
- 发送前取消是不发送；发送后停止等待不等于工作台撤回了可能已经收到的引用。重试不得被描述成旧请求肯定未送达。
- 已收到的回执可作为本次历史保留，不能据此证明当前仍连接。第二个对象的请求不继承前一个成功。
- 工作台返回“一般性的后续需处理”时，网页只给 `Continue in Open-Science`，不展开 GitHub 授权/权限诊断。
- 所有重试都由明确操作触发；恢复页面、连接或选择不能自动重发。

### 5.4 本机状态和场景隔离

| 数据 | 要保持的行为 |
| --- | --- |
| 路由、搜索、筛选、排序、分页、对象 | 正常开关连接面板不改变；断开不跳首页；普通站内导航保持当前页面会话 |
| 收藏、最近浏览、说明语言 | 明确属于本浏览器；收藏及最近浏览仅连接后可用，未连接不新增历史、不修改个人库，断开保留已有记录；说明语言不受连接限制；存储损坏或被禁用时退回内存并提示 |
| 工作台连接、发送资格、Demo 回执 | 不从持久 `connected=true`、旧确认、URL 参数或历史记录恢复；完整刷新/新标签页重新确认连接 |
| 待处理对象 | 可以恢复选择与有效返回位置；重新查对象和引用，撤回/缺失时禁止发送，重新连接并审阅 |
| 示例、Review 场景偏好 | 独立临时域，不进入真实目录、统计或普通持久收藏；场景内取消收藏不能删除普通收藏 |

生产存储键名不需要照搬 `aipoch-network-v9-r2.*`；现有偏好迁移应验证结构并保留旧数据。真实协议未来若支持会话恢复，也必须先重新验证，不能直接恢复 UI 的已确认标志。

演示场景进入/退出必须取消失效等待，拒绝旧域回执，不恢复 Sending 或自动重发；只保留仍有效的普通会话。复位使旧连接/请求失效，但不能清除普通收藏。场景响应设置不得泄漏到正常模式。

## 6. GitHub、目录与公开推荐

仓库、科研项目、可复用资源是不同实体，保留多对多引用。`Capabilities` 是用户界面的能力表达，不要求把实施项目通用 `resource` 数据类型改名。

真实页面从实施项目自己的目录生成。原始观察、人工补充及生成描述继续有来源；不得把示例叙事变成维护者声明，或因为要填满卡片而补造科研阶段、输入输出、效果与验证结果。

HTML 中冻结目录的数量、观察日期、特定项目顺序和示例名称是设计输入，不是生产硬编码目标。不要为了复刻截图而删除实施项目已有条目、回退到旧快照或改动当前目录事实。数据更新允许改变数量与内容，但不能删除来源说明、未知状态和关系语义。

完整研究引用至少表达对象/类型、动作、公开位置、目录快照或等价版本依据、全部来源、许可和条件。来源已提供且适用时保留完整修订/SHA 和路径；未固定版本、缺失字段或非 Git 来源明确保留未知/不适用状态，不得补造 SHA 或路径。原型 JSON 字段、`design_review_revision` 和 module 名称不是正式 Connector schema；短 SHA 只用于显示，不能取代真正传递的完整版本信息。

公开推荐流程保留：输入公开仓库/组织/文件地址 → 展示准确草稿和范围 → 用户审阅 → 显式打开目标页或复制完整文本。编辑内容使原确认失效。源项目协作和目录纠错使用各自目标；打开 GitHub 草稿页后不得自动标已提交、已合并或已收录。超长链接及复制失败时提供完整可选择文本，不静默截断。

## 7. 将设计落到独立工程

GitHub Actions 批量生成目录和部署静态产物与本方向兼容，它不是实时业务后端。沿用接收项目的架构、依赖、路由和公共契约。在 aipoch-network 中，网站展示属于 `web/`；目录维护、模式、采集生成和消费者各有自己的模块。这是映射提示，不要求其他实施项目采用同一目录名。

本次视觉/交互接纳不要求修改目录 schema、采集认证、GitHub Actions、发布权限或上游项目。Network 构建不得导入 Open-Science 内部类型、数据库、IPC、凭据、发布产物或测试服务，也不得依赖 med-research-ai 的 store 和生成脚本。

参考 HTML 可以原样归档和用于设计对照，但不要将它的整包编译脚本、嵌入目录副本和依赖集直接替换生产网站。生产应从自己的源码和当前数据构建，保留静态页面可读性、搜索恢复、历史链接、来源关系与子路径支持。素材和第三方声明保留原归属；目标项目代码许可证不自动替代素材、上游内容和依赖各自的条款。

### 技术上可自主决定

组件边界、状态管理库、CSS 实现、静态路由对应方式、内部变量名、测试组织、合理的响应式断点、无障碍修正，以及兼容既有数据契约的映射。无需为每个选择另起产品审批，但应通过行为和视觉对照验证。

### 不从本稿推断的范围

新增账号/云同步、研究数据托管、远程执行服务、常驻后端、收费交易、自动镜像完整仓库、改变仓库可见性、生产发布，以及真实 GitHub 授权流程。是否执行这些工作由相应明确任务决定，不因 HTML 中有按钮而自动开始。

## 8. Demo 如何交接到生产

本 HTML 的连接和回执均为本地 **Demo**，没有真实客户端接收，也没有真实应用唤起。正常按钮可触发演示确认；Review 提供无响应、失败、手动/过期响应等测试控制。这些机制用于说明目标行为，不是产品已经具备的底层能力。

| 已确定的行为 | 尚未确定的生产实现 |

## 11. 后续版本与常见偏差

后续继续以新版 HTML + 配套 MD 传递设计。每次写明二者版本/摘要、全量或局部替代范围、保留约束及变化清单；只有文字补充时保留 HTML 摘要并递增 MD 修订。影响可见设计或交互的变更应在下一份匹配 HTML 中体现，不能长期依靠 MD 悄悄改写旧稿。接收项目保留原件、更新目标映射、按实际范围重新验证。

- 顶部重新出现 My Network、GitHub 登录或第二个 Saved 入口。
