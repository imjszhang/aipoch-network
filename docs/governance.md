# 目录治理规则

本文规定来源收录、修改、撤回、维护者认领与组织策展的处理规则。它补充[目录契约](catalog-contract.md)与[交付运行规则](delivery-operations.md)，不设立新的账号、后台服务或独立协作平台。

The repository is public and GitHub Issue Forms provide public intake. Follow the [issue routing policy](issue-routing.md) to separate catalog requests from product issues. Public availability does not establish full acceptance using an ordinary external account.

## 1. 决策与职责

| 角色 | 职责 | 权限边界 |
| --- | --- | --- |
| 投稿者 | 推荐来源、提交纠错、提供可核验资料 | 投稿或编辑不赋予上游维护权或组织代表权 |
| 目录审核者 | 核对来源、范围、证据与重复，记录决定 | 审核目录事实，不代表原作者批准研究结论 |
| 认领审核者 | 核对 GitHub 身份、授权对象和范围，执行复核或撤销 | 不凭 PR 作者身份自动确认认领；不能审核自己的认领 |
| 发布维护者 | 检查当前撤回范围、候选产物与恢复材料，记录发布结果 | 仅在既有授权和可见性边界内发布 |
| 项目所有者 | 确定仓库与公共协作布局、发布范围、责任人 | 公开决定另行记录，计划或模板不构成授权 |

初期一人可以承担多个日常职责；涉及该人自己的认领时需要另一名有权限的审核者核实。没有独立审核者就保持待核验，不能以自我声明升级状态。每个决定保存执行者、时间、依据、范围和结果；不要求为了基础收录建立复杂组织结构。

## 2. 收录决定

候选的最小内容是公开 GitHub 仓库或组织 URL。支持具体目录或文件位置归一到来源仓库，保留原定位；无法识别的输入说明问题并等待纠正。无需 AIPOCH 清单、原作者配合、Stars 门槛、特定许可证或可运行配置。

审核逐项确定：来源是否可公开读取且身份可确认；是否与科研有关；是否已有同一来源身份；描述是否准确且能追踪出处；是否有有效撤回或抑制记录。可公开读取不等于获准复制、运行或再分发。资料不足时收录最小来源入口，留空或标明未知，不强行创建虚构的研究项目和资源。

| 决定 | 适用情形 | 记录与后续 |
| --- | --- | --- |
| 候选，待审核 | URL 可识别，尚未完成核对 | 保留输入、检查结果与待处理事项 |
| 待补充 | 暂时无法确认来源、重复关系或研究相关性 | 列明缺少的事实；不用一次请求错误推断删除 |
| 收录 | 来源和描述达到基础收录要求 | 关联目录稳定 ID、审核记录和变更 PR |
| 合并重复 | 同一 GitHub 稳定来源 ID 已存在 | 保留一个来源身份；涉及不同资源时保留资源区别；旧目录 ID 用最小重定向解释 |
| 退回 | 不属于范围、恶意提交或无法纠正的错误 | 给出理由和可申诉/重提方式；不靠无解释关闭处理 |
| 撤回或被替代 | 经核实需要移除或身份/范围已改变 | 保留不泄露内容的最小状态；详细清理按第 5 节 |

以上是治理流程用语；写入文件时使用实际 schema 定义的枚举，不能为流程方便自造不兼容字段。校验通过和 PR 合并不自动等于每个候选已收录。

## 3. 来源、描述与争议

来源观察、人工补充、派生产物分别管理。GitHub 稳定来源 ID 决定身份，名称和地址变化只更新经验证的定位。旧路径被新仓库占用时不继承原目录的认领、版本或审核结论。

人工研究摘要与原始 README 分开保存；自动提取、社区描述、维护者声明和目录编辑分别标明。来源更新不直接覆盖人工意见，也不让过期摘要继续假冒当前上游声明。许可证按具体来源、路径和版本记录，冲突时保持不确定。

描述争议先定位对象、字段、版本和依据，必要时暂时收起有争议的主张，保留安全的来源入口与“待复核”说明。审核者比较证据并给出修改或维持原因。申诉可在原 Issue 或关联的新 Issue 提供新增依据；有利益冲突的审核者回避。无法得出结论时保留争议，不把未证明的说法标为维护者确认。

## 4. 维护者认领与组织策展

### 分开核验三种事实

| 事实 | 可支持的结论 | 不足以支持的结论 |
| --- | --- | --- |
| 社区推荐和目录审核 | 某来源已被整理 | 作者主动参加或认可 AIPOCH |
| 仓库维护者明确声明，控制/授权依据已核验 | 某 GitHub 身份对该仓库指定维护范围负责 | 该人代表整个 GitHub 组织或线下机构 |
| 组织 owner 权限已核验，或该 owner 明确委派策展范围 | 指定身份对明确组织目录范围进行策展 | 组织全部现有和未来仓库自动加入、全部成员同意、科学有效性得到认可 |

仓库认领可以使用原仓库维护流程中的授权确认或经核验控制的默认分支/官方文档声明。审核者核对声明作者身份和对应权限，而非仅确认某段文字存在。组织认领需要另行核对 owner 身份和明确授权；组织仓库写权限、普通成员、提交记录或自称 owner 不能替代这一步。

优先使用公开、最小范围证据。若 owner 权限不能公开确认，只有认领者主动发起且已约定受限核验方式时，才在必要的最小权限范围核验。目录不收集令牌，不存非公开成员列表，不要求全体成员公开身份。无法充分证明时保持待核验。公开摘要可写核验方式、日期、审核者和范围；敏感原件只在约定的受限位置保存，不能写进未来会公开的 Git 历史或构建包。

### 每次认领必须留存的审计信息

- 请求与决定的关联 Issue/PR、对象稳定 ID、GitHub 来源数字 ID。
- 声明主体的 GitHub 数字 ID 与当前账号定位，仓库维护或组织 owner/委派的核验类型。
- 具体授权范围：对象、字段、仓库/资源清单、版本或有效期；没有全组织默认通配授权。
- 证据 URL、观测时间、内容版本或摘要，以及需要时的受限证据引用。不得在公开记录中写出受限位置的访问凭据或私人材料。
- 审核者、审核日期、结论、复核期限或条件、撤销原因；声明主体与审核者分开。

这是一份审计要求，不意味着所有内容属于公开契约字段。按现有 schema 保存公开最小记录，超出部分放在适当可见性的审核记录中；生成器必须排除受限审计信息。

### 有限范围策展

组织候选和组织主动策展分别表达。社区可以从一个组织 URL 推荐资料；正式策展集合引用已审核仓库或资源的稳定 ID，并记录选择依据与有权维护该集合的主体。维护者可选择部分公开仓库、某几个资源或一个研究主题。未选择的仓库、后来新增的仓库和新增资源不自动进入集合，更不自动继承官方确认。

修改集合展示顺序、说明或成员列表仍需目录审核。扩大授权范围需要新的 owner 确认或已授权范围内明确允许的操作依据；集合成员变化不能改变来源所有权或替它授予许可。

### 复核、撤销与恢复

账号改名先核对数字 ID。仓库转移、owner 或维护权限变化、授权到期、证据链接失效、声明撤回和授权争议都触发复核。转移后即使仓库 ID 不变，也暂停继承原组织的授权结论。仅有别名变化不能将认领移给新身份。

认领从待核验到确认需要完整证据与审核；触发复核时停止展示当前有效确认，保留安全的复核状态；证据不足、授权撤销或误认时记录撤销。恢复需重新核验当前主体与范围，引用新证据，不能靠恢复旧文件自动回到确认状态。撤销认领不必撤下仍可公开读取的来源，但须移除失效的官方参与/代表主张。

## 5. 不可访问、撤回与重新收录

| 情况 | 处理 |
| --- | --- |
| 短暂超时、5xx、限流 | 保留最后有效来源观察并标时间；超过 48 小时显示软过期，超过 7 天未能重新确认公开则收起抓取字段 |
| 明确 private 或非限流 403/404 | 停止采集，不用更高权限读取；不武断区分删除和私有；立即加入下一次成功发布的清理集合 |
| 经确认的撤回请求 | 明确对象、字段、来源链接及历史产物范围；立即登记抑制记录并准备清理，不等待过期宽限 |
| 来源重新公开 | 可重新核验来源；有效人工撤回仍阻止重新收录，复核通过后才恢复 |

48 小时与 7 天是本项目运营策略，以最近成功核实公开的时间计算，按[交付运行规则](delivery-operations.md)实施；不是即时同步保证。源码归档仅表达不再活跃，并不自动表示不可读取或必须撤回。

任何人可报告信息泄露、错误来源或错误认领，维护者先核实可直接观察到的事实。主动撤回的代表权限按实际请求范围核验；无法确认代表权时不得允许第三方任意永久删除他人来源，也不得忽略有证据的隐私或公开状态问题。需要保护内容时先收起有依据的争议部分，完成复核再决定最终范围。

清理覆盖页面 HTML、目录 JSON、网站搜索数据、站点地图、图片、详情和仍可直接下载的旧快照。检查历史日志、artifacts 和 cache 是否含同一撤回字段。明确不可公开访问或撤回时最多保留不泄露资料的条目 ID 与通用不可用状态；如果来源 URL 也在撤回范围内，必须移除。不得用旧快照恢复字段或将被清理来源换名重新引入。

保存一条最小抑制记录，让采集与回滚都能识别该来源；若识别资料自身不宜公开，放在事先确认的受限记录中。发布前将当前抑制集合应用于候选和恢复产物。无法可靠执行最新撤回的旧包不能直接重新发布。

静态发布只能在发现变化并成功更新后生效，不能收回用户已下载的副本，也不能通过删除当前文件消除公开 Git 历史。需要处理历史暴露时单独记录影响和恢复操作，不把改回私有或重写历史当作已清除所有副本。

### 已实现的历史快照处理

普通目录构建保留仍符合当前公开政策的历史快照。保留前重新检查 manifest、每片字节数、SHA-256、记录数、版本、快照 ID 和完整对象引用，只复制清单明确声明的文件；未经声明的文件和损坏快照不进入新产物。没有撤回或来源/授权变化时，旧文件保持原始字节和固定地址。分片方式变化产生新快照 ID，不覆盖旧分片。

当前撤回、来源压制或不可访问、超过 7 天未能核实公开、从审核范围移除以及有效授权状态改变，都可能使包含相关内容的历史快照整份退出公开产物。其他仍安全的快照继续保留。退出记录写在 `catalog/v1/history.json`，仅含快照 ID、时间、状态和通用原因，不保存被撤回的标题、URL 或证据。已退出的同一快照 ID 不因重新播放旧输入而恢复。

目前历史文件总保留预算为 64 MiB，历史记录最多 4,096 项；达到上限时构建停止并保留最近完整产物，要求维护者明确复核保留范围，不悄悄删除承诺过的固定路径。原始来源缓存及恢复输入仍是受限材料，不因历史目录可公开就自动上传。

恢复候选保留当前来源观察、审核成员范围、撤回、账号与授权记录，只恢复仍具相同稳定身份和适用来源范围的旧编辑字段。已撤回条目、移除的成员、旧授权、旧私有状态、旧 README 和无法与当前身份匹配的描述不能借回滚恢复。恢复结果是经当前政策重新校验的新快照，不冒充旧发布字节完全复现。实际操作与演练见[维护手册](maintainer-guide.md#历史快照与恢复候选)。

## 6. 审核记录与时效

每次处理应能从最初请求追踪到决定、目录变更和候选/发布版本。记录收到请求、最近核对、决定和实际清理完成的时间；尚未部署的私有候选不能写成已从公共站点撤下。优先处理已确认的内容撤回和权限问题，其次处理普通纠错与新候选。当前未设置已有人力保障的响应时限，不承诺自动即时受理。

维护手册提供[审核记录格式与操作步骤](maintainer-guide.md)。公共演练必须由实际无仓库特权的外部账号在经批准且可访问的入口执行；模板、维护者内部提交和离线模拟只证明各自范围，不能证明外部参与闭环。
