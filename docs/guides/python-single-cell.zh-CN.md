# 从单细胞表达矩阵出发，建立可复查的 Python 分析记录

资源指南 · 2026-09-14 · 面向能阅读 Python notebook 的研究生和科研分析人员

拿到一份表达矩阵后，第一件事可以是写清它的来历：哪些样本、哪些细胞、哪些基因，经过了什么处理，你准备回答哪个问题。把这些内容和后续参数、软件版本、判断依据放在一起，下一位分析者才有机会理解你为什么得到某个结果。

这篇资源指南给出一条选择工具和保存记录的思路。工具用途根据维护者资料整理，流程组织是我们的编辑建议。本次未运行这些软件，也未验证一套联合环境；下文不构成对任何分析结论的科学认证。

截至 2026-09-14 本次核对，正式目录已包含 [AnnData](https://aipoch.network/capabilities/resource~anndata-library/)、[Scanpy](https://aipoch.network/capabilities/resource~scanpy-library/) 和 [MuData](https://aipoch.network/capabilities/resource~mudata-library/)。本文另外九项工具仍是运营调研候选；其链接通往上游，不表示已收入目录。[本次核对的目录来源分片](https://aipoch.network/catalog/v1/snapshots/783da3beb22610ad5d9e3e2b/sources-0.json)

## 先把数据对象看清楚

AnnData 用于带注释的矩阵数据。官方入门以细胞为行、基因为列展示单细胞对象，细胞层面的信息放在 `.obs`，基因层面的信息放在 `.var`。这种组织方式让表达矩阵与两侧注释有明确的对应关系。[AnnData 官方入门](https://anndata.readthedocs.io/en/stable/tutorials/notebooks/getting-started.html)

从现有文件开始时，建议先做一页“数据说明”：数据的公开来源或内部访问位置、生成日期和版本；每一行/列代表什么；样本、批次与条件字段的含义；矩阵是计数还是已变换的数值。对无法确认的内容直接标为未知，并指出从哪里补查。文件格式本身不能替你证明这些语义。

这一页说明是后续方法选择的前提。例如，同一个字段名 `batch`，在不同材料里可能代表不同处理环节；不先读懂数据字典，就很难解释为什么采用某种整合设置。我们建议保留数据说明的修订历史，让后来发现的更正也可追踪。

## 用基础分析形成明确问题

Scanpy 的维护者将其定位为单细胞表达分析工具，覆盖预处理、可视化、聚类等能力。它与 AnnData 配合，但两者不是同一种资源：一个提供分析能力，一个组织带注释数据。[Scanpy 项目说明](https://github.com/scverse/scanpy)

起步时可以选择官方资料中的一个基础案例，先理解输入、参数与输出之间的关系。进入自己的数据后，把每一步写成可回答的问题：本步试图检查什么？使用了哪些字段？改变了多少细胞或特征？选择这一阈值的依据在哪里？这些是我们建议保留的分析笔记，不是一套对所有实验通用的参数表。

图形只是记录的一部分。除了保存图，还可以保留产生该图的输入版本、步骤顺序、参数和结果对象。后来发现某个样本注释有误时，这些关联能帮助你判断应从哪里重做。不要仅凭视觉上的分群效果，把尚未核对的细胞身份写成已经确认。

## 只有出现整合问题时，再增加模型与评估

scvi-tools 提供单细胞组学的概率建模工具，包含多种分析任务；它的模型有各自的输入与接口。浏览这个项目时，应先选定要解决的问题和具体模型，再读相应文档。项目拥有整合能力，并不证明你的数据与某个模型已经适配。[scvi-tools 项目说明](https://github.com/scverse/scvi-tools)

可以先写一张“模型选择卡”：目标问题、必需输入、训练所用数据范围、参数、随机性设置、软件与依赖版本，以及准备如何评估结果。若使用额外硬件，记录实际环境。该卡片是本指南的记录建议；兼容性要求以所选模型的官方文档与实际环境验证为准。

scIB 是一个用于整合分析与评估的 Python 包。维护者同时链接了独立的 pipeline 和研究复现仓库，因此软件包、执行流程和研究结果应分别阅读与引用。[scIB 项目说明](https://github.com/theislab/scib)

评估之前先说明你希望保留的生物学结构、要处理的批次差异，以及所用指标能回答什么。不要把一张可视化图或一个总分作为所有判断的替代。对某次 benchmark 的结论，应保留其数据与版本范围；本指南没有重新比较方法，也不提供“当前最佳方法”的排行榜。

## 按数据和问题选择扩展分支

普通表达矩阵的起步流程不必同时装下全部生态工具。下面的分支用于确定下一份该读的文档，每一项都需要自己的输入与方法审阅。

| 当你遇到的问题 | 可以进一步阅读 | 阅读时先确认 |
|---|---|---|
| 多个模态如何组织与分析 | [MuData](https://github.com/scverse/mudata)、[muon](https://github.com/scverse/muon) | MuData 是容器/读写库，muon 是围绕它的分析框架 |
| 如何进行组学富集解释 | [decoupler](https://github.com/scverse/decoupler) | 所选方法与先验资源的来源、版本、许可 |
| 数据包含 TCR/BCR 信息 | [Scirpy](https://github.com/scverse/scirpy) | 受体信息是否真实存在、如何与细胞对应 |
| 研究的是扰动实验 | [Pertpy](https://github.com/scverse/pertpy) | 实验条件、对照和元数据是否满足具体分析 |
| 研究细胞动态过程 | [scVelo](https://github.com/theislab/scvelo)、[CellRank](https://github.com/scverse/cellrank) | 选择的方法依赖哪些输入和先验；推断结果如何表述 |
| 数据含空间位置或图像 | [Squidpy](https://github.com/scverse/squidpy) | 空间数据及图像的来源与对应关系 |

表中的用途来自各维护者项目说明，阅读顺序与输入核对建议由我们整理。MuData 已收录，其余分支工具仍为调研资料入口，不代表已全部收入 AIPOCH Network，亦未获得维护者对本专题的认可。

## 让后来的人能找到依据

每完成一个小阶段，建议留下一份简短记录：

1. 输入：来源、版本、获取日期、校验信息和访问条件；敏感数据保留在被授权的位置。
2. 方法：软件与依赖版本、官方说明链接、实际参数、步骤顺序和必要环境信息。
3. 输出：结果文件与图对应哪一次运行；哪些步骤失败或没有执行。
4. 判断：哪些内容直接来自结果，哪些是解释或假设，还需要什么证据。

这份清单是编辑建议。记录完整让别人更容易复查，但不能替代实际重复运行、方法评估或科学验证。团队若已有规范，优先把这些信息放进原有流程，避免多处维护不同答案。

AIPOCH Network 的角色是帮助读者发现资源、查看来源并回到上游。基础浏览不需要安装工作台；上游代码、文档和协作仍保留原位。目录收录也不等同科学背书。产品原则见 [Network 说明](https://github.com/imjszhang/aipoch-network/blob/cd2e003542dc873e473f694d200ca9e0449323dd/README.md)。

本文的首个可完成动作是：为你手上的一个矩阵写好数据说明，再选定一个基础分析问题。你在这一步遇到的缺口，往往比再增加一个工具名字，更能告诉我们下一篇资源指南应该写什么。
