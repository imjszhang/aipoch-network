## 2. 三个可选范围

| 选项 | 保留与公开的范围 | 投稿与站点 | 需要明确的选择 |
| --- | --- | --- | --- |
| **A：继续私有验收** | 主仓库、Git 历史和 Actions 资料继续受现有私有访问控制；本地完成候选检查 | 本地静态预览；只有已有仓库权限的人能提交 Issue/PR | 维持当前状态即可继续技术工作；A12、A20 的公共部分及正式部署保持待执行 |
| **B：准备公开主仓库并用 Pages 发布** | 经审查的主仓库文件及可访问 Git 历史公开；代码、目录、规范、Issue/PR 与构建流程集中维护 | 公共 Issue/PR 为投稿入口；完整静态产物部署 Pages | 明确批准主仓库公开范围、各类内容许可及 Pages 公开；处理原始 HTML 内嵌第三方内容的分发范围后才能执行 |
| **C：主仓库长期私有，另设公共目录与投稿仓库** | 私有实现与受限资料保留；只向新公共仓库交接已审查的目录、规范、治理资料和发布内容 | 新公共仓库承接 Issue/PR；Pages 的来源及产物交接方式另行固定 | 明确授权新增公共仓库，指定 owner/name、权威数据位置、发布仓库及最小权限交接方式；当前没有此仓库或凭据配置 |

既定架构优先评估 B：一个仓库承担公开协作和维护，变更链条较短。它仍取决于内容与许可审查，不能因为实现方便而提前公开。A 可以完成所有不依赖公众入口的技术验收；C 需要补充跨仓库实施与验收，不能把它描述为改一个设置即可完成。

### B 的具体候选范围

拟议站点是 `https://imjszhang.github.io/aipoch-network/`，构建基路径为 `/aipoch-network/`，公开静态接口为该站点下的 `catalog/v1/manifest.json`。这些是**拟议地址**，不表示地址已开通。若选择根站或自定义域名，须重新固定域名、基路径和对应测试结果；当前不新增域名或 DNS 操作。

投稿入口拟继续使用 `imjszhang/aipoch-network` 的 Issue/PR。网站当前“Private development”“Repository access required”等说明须在实际开放后按新事实更新，保留“GitHub 草稿尚未提交”的真实操作边界。

### C 的具体交接原则

1. **只有一处可编辑的权威目录。** 建议公共仓库成为 `registry/`、公共 `spec/` 和公开治理记录的唯一维护入口；私有实现只读取经审核的固定公共 commit。迁移时列明文件和初始 commit，不在两仓库同时手工维护同一份注册资料或规范。
2. **兼容版本可追溯。** 私有构建锁定公共提交、契约版本和文件摘要；公共 manifest、恢复报告及候选记录标明对应版本。网站内部搜索数据继续独立；公共 v1 的既有语义和仍允许公开的历史快照不因分仓而改写。
3. **发布位置必须确定。** 可以从具备相应资格的私有仓库发布公开 Pages，或把经过验证的静态包交给公共仓库发布。前者仍需套餐核验，后者需包摘要、输入版本、公开文件清单及接收方验证；不得以一次普通目录复制代替交接。
4. **权限按操作分配。** 公共 PR 检查不获得私有仓库读取、来源采集或发布权限。私有受信构建可以读取公共固定输入；若自动向公共仓库写入，另行审查仅安装于目标仓库且只具所需写入能力的身份。不得默认现有 `GITHUB_TOKEN` 能写另一个仓库，也不提前创建 GitHub App、PAT 或 secrets。
5. **先证明事件和撤销流程。** 用选定身份实际验证提交后检查能否触发、旧任务不会覆盖新候选、权限撤销时交接会停止，以及跨仓库恢复仍使用最新撤回记录。仅拉取到公共数据不等于完成发布回执。

C 的新增仓库名称、归属、规范迁移、发布位置及写入身份尚未确定，均不得自行代填为已经存在或获得授权的资源。

当前没有已选择并落盘的项目 `LICENSE`/`NOTICE`。应分开确定本站代码、AIPOCH 原创目录文字和原始设计材料的处理；上游代码、说明、数据和图片继续遵循各自条款。本文件不代填任何许可文本，也不将“URL 可收录”解释为允许复制或再分发上游内容。

原始 v6 HTML 的归档校验值和大小见 [设计记录](../design/README.md)。它不是生产入口，不由构建自动复制到站点。如果其公开分发范围仍不明确，B 不能直接公开含该原件的全部历史；需先确定允许公开的内容范围或改选保留私有的方案。仅从最新文件树移除原件不会移除 Git 历史；任何另建公开历史或重写历史都应作为具体、单独审查的变更，不自动执行。

`.cache/`、`.env*`、本地 previous/staging 输出、原始响应和受限恢复材料不在站点交接范围。现有忽略规则只能防止普通新增提交，不能证明过去从未提交或记录过这些内容。公开内容审查应覆盖选定分支、可达提交、标签，以及实际仍可访问的协作记录和 Actions 资料。
