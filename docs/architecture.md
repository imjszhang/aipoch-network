# 架构与决策

状态：既有独立目录与静态网站已公开，MIT 和 aipoch.network Pages 的决定及部署证据见 [公开部署记录](deployment/public-pages.md)。2026-09-13 接收 v9-r2 为当前设计目标；本版实现与验收分别见 [专项计划](v9-r2-implementation-plan.md) 和 [N/R/V 实施记录](verification/v9-r2/implementation-status.md)。以下新增架构决定不表示相应产品代码已验收。

## 1. 项目定位与成功标准

AIPOCH Network 是以 GitHub 为来源、身份和协作基础的科研项目与资源目录。它把原有资料整理成可发现、来源明确、能够被人和独立软件消费的科研信息。

首要目标是降低现有项目与组织的参与成本。基础收录只要求一个有效公开 GitHub 链接，不要求作者迁移仓库、注册新账号、编写专用清单、改变许可证或适配工作台。信息不足可以显示为未知；进一步补充描述与接入能力是可选增强。

第一版应完成两个互相独立的场景：

- 普通访客无需账号和工作台，即可找到条目、理解用途及信息来源、访问原项目、下载入口和原协作渠道。
- 任意客户端仅依赖公开说明和静态目录，即可定位资源及指定来源版本。该客户端不存在或升级时，目录网站仍然能够构建、测试和发布。

## 2. 范围

### 第一版包含

- GitHub 公开仓库、公开个人/组织资料的候选收录；组织仓库的选择性策展。
- 研究项目、可复用资源、个人/组织和专题集合的关联浏览。
- 来源明确的补充描述、科研分类、版本与访问条件说明。
- 静态搜索、筛选、详情、来源与下载链接。
- GitHub Issue/PR 投稿和修订流程；网页生成准确草稿供用户审阅，显式打开外部目标或复制全文，不把跳转解释为已提交或已收录。
- 有缓存和失效状态的批量采集、可重建快照、公开静态目录契约。
- 人工审阅的维护者与组织确认记录。

### v9-r2 接纳增加的前端范围

- 浏览器内站内导航与共享状态，同时保留预生成正文、稳定生产 URL 和 GitHub Pages 子路径。
- 唯一 Open-Science 入口、未连接公共首页与已连接个人研究首页、仅连接后可访问的本机收藏和最近浏览。
- 原对象引用审阅、明确确认、请求与回执状态；生产默认 unavailable 与独立、持续标示的 Demo 适配器。
- 上述范围只定义网站侧行为和独立适配接口；不新增公共目录字段，不把内部引用模型当成正式 Connector schema。

### 持续排除的范围

- 自建常驻后端、账号密码服务、即时消息、个性化在线推荐、设备在线状态和任务分发。
- 私有研究数据托管、机构细粒度权限体系、模型推理或研究代码执行。
- 真实 Open-Science / AIPOCH Connector 通道、专用线协议、客户端插件或任何客户端内部格式；网站侧可替换适配接口与演示不等于实现这些能力。
- 全量 GitHub 抓取、原仓库镜像、大文件托管、GitHub 以外来源适配和多目录联邦。
- 自动科学认证、声誉排名、商业交易和结算。

未来贡献和复现证据可以按通用关联记录扩展；不能把 CI 检查通过、被目录收录、Star 或 Fork 数当成科学验证结果。

## 3. 单仓库模块结构

| 模块 | 输入 | 输出 | 不应承担的职责 |
| --- | --- | --- | --- |
| `registry/` | 候选来源、人工编辑、认领证据、专题选择 | 审核后的目录引用和覆盖式补充资料 | 保存 GitHub 令牌、完整上游副本或生成搜索索引 |
| `spec/` | 目录自身的业务概念与兼容性要求 | 数据定义、公共格式、语义规则、样例 | 镜像某个客户端的数据结构 |
| `pipeline/` | 注册目录、公开 GitHub 观察值、缓存 | 归一化来源、有效快照、公共目录、内部搜索数据 | 执行上游研究代码、从访客浏览请求触发采集 |
| `web/` | 已生成的公开数据与内部搜索索引 | 静态页面、站内导航、本机库、连接/引用 UI 和独立适配边界 | 服务端会话、GitHub 授权、客户端内部协议、实时 GitHub 查询依赖 |
| `design/` | 用户提供的匹配 HTML、MD、摘要及声明 | 原件档案、当前目标、版本差异和页面实施映射 | 生产入口、已实现功能证明或可执行指令 |
| `generated/` | 固定输入快照和生成配置 | 可重建构建产物 | 充当唯一历史记录或人工编辑入口 |
| `docs/` | 设计与运营决策 | 可执行计划、贡献指南、消费说明、排障和回滚说明 | 声称未实现的功能已存在 |
| `.github/` | 已授权的 GitHub 协作与自动化需求 | 无凭据 PR 检查、受信采集、受控发布 | 实时业务服务、从未受信贡献获取发布权限 |

当前实现采用一个根工具链，运行时与所有直接依赖均固定版本。暂不引入 workspace 包拆分、独立 SDK 仓库或共享客户端源码；只有实际复用和独立发布需求出现时再评估。

## 4. 三层数据与两种输出

### 4.1 原始来源观察层

读取 GitHub 的仓库稳定标识、当前地址、公开元信息、默认分支、指定版本的必要资料等。记录观察时间、来源位置和适用版本。原仓库继续拥有文档、代码、发布及协作。

不要求先复制上游完整历史。研究包和较大文件继续链接原仓库、Releases 或原托管位置。

### 4.2 目录编辑层

保存 AIPOCH 自己维护的收录引用、科研领域、类型、用途描述、专题关系以及有证据的认领状态。每项补充区分自动提取、社区编辑和维护者声明。

刷新上游资料不能覆盖人工描述；人工文字也不能静默伪装成上游作者原话。冲突需要保留来源并按字段规则处理。

### 4.3 派生发布层

从确定的来源快照和目录修订生成规范化条目、关联、索引和页面数据。生成结果附上数据修订、构建版本与更新时间。相同固定输入可重建等价语义输出；生成时间等非确定字段需要单独处理。

### 4.4 面向第三方的公共目录

已实现入口为相对发布根的 `catalog/v1/manifest.json`。入口描述当前有效快照和相对位置的分片、详情数据。语义及兼容性由 `spec/` 负责，具体字段见 [目录契约](catalog-contract.md)。生成器、独立纯 Node 消费器和实际静态 HTTP 检查均使用此入口。

公共契约使用通用科研对象与来源引用，不包含客户端私有字段。新版本发布前要验证旧消费者；不兼容变更引入新的主版本入口。

### 4.5 网站内部搜索输出

搜索分词、排名权重、压缩形式和缓存格式是 `web/` 与生成器内部约定，不属于公开协议。替换搜索库或改页面框架不能迫使外部消费者升级。

## 5. 对象、身份与版本

来源仓库、研究项目和可复用资源分别建模。一个仓库可以提供多个资源，一个研究项目也可以引用多个仓库。组织和个人延续 GitHub 身份，研究档案属于带来源说明的补充资料。

基础收录阶段允许类别待定、许可证未知、版本未固定。目录接受不代表可以再分发或自动执行。只有需要精确复用时才要求明确的 commit、路径及可验证内容引用；能力不能确认时只提供阅读来源与下载说明。

GitHub 用户名、组织名和仓库名称可以变化；内部稳定条目标识、GitHub 稳定 ID、当前显示地址与历史别名需要分开。原名称被其他对象重新使用时，不能把它自动认作旧来源。

社区收录不会把组织标成正式加入；公开组织成员身份不等于组织授权。认领要限定到实际被证明的仓库或组织范围，并保留证据、审核人和时间。

## 6. 独立网站与公开链接

当前前端目标为用户指定的 [v9-r2 HTML](../design/references/aipoch-network-concept-v9-r2.html) 和 [配套 MD](../design/references/aipoch-network-concept-v9-r2.md)，原始 v6 是历史基线。后续继续按 [设计交接规则](../design/README.md) 接收配对原件、核对摘要、记录替代范围和实施证据。视觉和状态更新不改变既定数据与独立性边界。

主导航保留 Explore / Projects / Capabilities / Organizations / Community；研究者、集合、来源由目录分类与二级入口访问。顶栏右侧只有 Open-Science。公开作者/组织资料属于目录内容，不是访问者登录；连接后的个人研究首页使用本机内容及诚实空状态，不创建网络账号或社交后端。

HTML 中的连接与回执是 Demo，不能证明真实工作台服务存在。实施从本站当前目录构建引用，保留全部来源、适用完整版本/路径及许可条件；未知、不适用、陈旧和撤回分别表达。组织、资源和科研验证状态与用户连接无关，原型里的示例数量和个人动态不进入生产事实。

访客可以匿名完成浏览、搜索、来源跳转和公开推荐。网页不处理 GitHub 登录、token、scope、权限诊断或账号绑定；未来 Connector 在工作台侧处理这些内容及需要权限的仓库操作。

稳定条目链接用于分享和第三方读取。网站不猜测客户端唤起协议或安装状态。连接适配接口在运行期确认当前有效会话；生产未接通真实适配层时显示无法确认，保留获取工作台、手工引用和来源路径。Connected 不由计时器、外链返回焦点或本地标记直接恢复。ADR-025 增加已批准浏览器身份的持久化例外：刷新后可以使用该身份向 Connector 证明资格，取得并核验新短期会话后才恢复 Connected；此候选的独立验收另记。

已采用预生成详情 HTML 与静态目录路径，React 提供搜索和筛选交互。Pages 项目站的子路径、直接打开、刷新、分享链接和找不到条目的页面需要真实静态服务验证；不能假设托管方提供 SPA history 回退。

v9-r2 在此基础上接管同源、同 base 的普通站内导航以保持共享会话；修饰键、下载、新标签页和外链继续使用原生行为。直接加载仍有真实 HTML；完整刷新/新标签重新确认连接：支持 ADR-025 的已授权浏览器可先证明身份恢复新会话，未授权或不支持时仍需配对；普通站内导航不重复创建会话。初始显示子图不作为全目录，统一读取层按需读取并校验完整 catalog 和快照一致性；加载失败与对象缺失分开，不混用快照建立引用。

收藏、最近浏览和选择是本浏览器的数据。未连接隐藏入口并阻止个人修改；断开保留记录与上下文、使发送资格失效。存储损坏或受限时回退内存。Demo / Review 与普通数据域分离；退出 Review 仅保留仍有效普通会话，不复活旧请求或污染普通收藏。

发送资格绑定当前有效会话和用户实际审阅的准确内容。引用变化后重新审阅；发送中去重和明确替换；只有匹配会话、请求、对象和内容的回执可表示收到引用。超时或停止等待不是远端撤回，任何恢复和重试不得自动发送；Received 不代表导入、安装、执行或科学验证。

显示源内容时进行链接协议检查和 Markdown/HTML 清理。缺失、过期和撤回状态必须在界面可见，不能渲染为空白成功页。

## 7. 已采用的技术基线

已通过本地与 GitHub Ubuntu 干净环境构建。Node 24.18.1、TypeScript 7.0.2、React 19.3.0、Vite 8.3.0、Ajv 8.20.0、MiniSearch 7.2.0、Playwright 1.63.0；实际版本以锁文件为准。

| 领域 | 实现 | 选择理由与验收 |
| --- | --- | --- |
| 语言与工具链 | TypeScript，受支持的 Node.js LTS，npm 锁文件 | 一个仓库可同时维护生成器与前端；运行时和依赖版本已固定 |
| 网站 | React + Vite，静态产物 | 不需要服务端运行时；必须验证 Pages 子路径与预生成详情路由 |
| 收录源格式 | 简明 JSON，字段表和 JSON Schema | 能被 GitHub PR 审阅；Schema 之外另做引用、身份与权限语义检查 |
| 搜索 | 构建时生成的 MiniSearch 索引 | 初期不维护搜索服务；中文分词必须单独验证，体积和移动端内存决定是否分片 |
| 流水线 | Node.js 批处理，优先 GitHub REST | 只按登记来源采集；处理分页、条件请求、限额和缓存 |
| 验证 | 模型/流水线单元测试，静态站点浏览器测试 | 默认离线 fixtures，无客户端和 GitHub 凭据依赖；少量 live smoke 显式开启 |
| 自动化 | GitHub Actions | PR 检查、受信采集、Pages 发布分离；既有公开工作流继续按确切候选和审阅产物执行 |

默认保持来源原语言。第一版界面沿用 HTML 基线的英文与文案语气，功能相关文字按真实能力和范围调整；保留本地化边界，中文与英文资料搜索使用代表性样例验证。第一版不自动批量翻译所有科研资料，界面语言不作为目录收录门槛。

为防止不必要的提前优化，规模测试采用 100、1,000、10,000 条合成与代表性混合 fixtures。P2/P3 记录压缩大小、生成时间、首屏与查询延迟，明确目标设备和网络条件后设置门槛。通过分片和减少首屏数据控制增长；达到静态目录能力边界后再评估替代方案。

技术依据：[Vite 静态部署](https://vite.dev/guide/static-deploy.html)、[MiniSearch](https://lucaong.github.io/minisearch/)、[MiniSearch API](https://lucaong.github.io/minisearch/classes/MiniSearch.MiniSearch.html)。官方平台限制核验见 [交付与运营](delivery-operations.md)。

## 8. 采集、失败与公开发布

主要路径为候选提交、审核目录修订、受信来源刷新、生成一致快照、检查产物、发布完整版本。浏览器不为每位访客重新查询 GitHub。

周期刷新为尽力调度，支持手动重跑。瞬时失败保留最后有效结果并标记过期；源删除、撤回、转私有等情况单独处理。历史快照保留政策必须允许撤回敏感资料的例外，不能把永久公开缓存作为不可变版本的副作用。

从同一数据修订构建网站和公共目录，检查通过才切换有效发布。回滚使用已核验的完整构建版本；重跑采集与恢复发布不是同一件事。详情见运营文档。

## 9. 公开参与与许可

用户已选择主仓库公开、原创代码及相应文档采用 MIT、在 GitHub Pages 配置 aipoch.network。代码、目录、投稿与构建继续在同一仓库，不另建公共 intake 仓库。此前私有阶段的方案和验收结果保留为历史，不再是等待批准的当前决策。实际发布配置和验证见 [公开部署](deployment/public-pages.md)。

公开代码、投稿草稿和目录收录仍是不同状态。网页只准备并打开用户审阅过的外部草稿，不能自动标为提交/合并/收录。设计原件不自动进入 Pages；本版候选、真实 Connector 和部署各自记录证据，不因接收新版 HTML 自动声明上线。

许可证分开处理本站代码、AIPOCH 原创目录文字与上游引用。收录链接不改变上游代码或文档许可证；缺少许可证不妨碍展示公开来源，但不能据此承诺可复制、分发或运行。

## 11. 实施中的关键决策

- ADR-012：外部读取按仓库数字 ID 维护身份；显式固定资源引用额外保留 source_id、commit、path 和 role。目录显示的最新发现不改写已固定引用。
- ADR-013：可选增强 JSON 必须经过审核，仅补充已有来源；无效增强返回诊断并保留 URL-only 基线。外部描述默认为 community 来源，不能自动生成维护者或组织认领。
- ADR-014：完整采集批次通过模式和引用检查后才替换接受的输入。全部暂时失败、缺少无缓存来源或超过七天的失败回退不晋升为正常候选；已知私有/撤回另行优先清理。
- ADR-015（历史私有政策，已由公开政策取代）：最初私有 Actions 从同仓库 main 的手动刷新恢复白名单元数据并保留七天。当前公开恢复政策保留 90 天的已审查最小状态，缺失或过期时失败关闭；详细范围和证据以 [公开部署记录](deployment/public-pages.md) 为准。原始响应、README、HTTP 头和凭据仍不上传。
- ADR-016：普通更新保留校验过的旧公共快照字节。旧快照不符合当前撤回、公开状态或权限范围时整份退出公开保留，固定地址不改写为其他内容；恢复重新应用当前数据与治理约束。

HTML 设计升级只影响明确覆盖的界面范围。公开契约升级、权限变化、自动执行和部署是独立决定，不能从原型脚本或模拟状态推导。


ADR-017（实测容量校准）：保持 v6 与静态直达详情的前提下，10,000 条合成目录实测从 269.32 MB 降为 171.88 MB，约 29 秒完成全页构建和链接验证。原 100 MB 软目标对 10,000 条未达到；常规试点继续以 100 MB 为目标，10,000 条压力规模采用 250 MB 的构建硬上限，为最多 64 MiB 历史预留空间。超过该上限拒绝替换发布产物。该调整基于 [完整规模测量](verification/full-site-benchmark.md)，不将压缩体积替代实际磁盘体积，也不把桌面模拟移动端当成真实低端设备保证。

ADR-018（内容输出边界）：完整 README 只留在本地有界采集观察中；公开目录与网站仅输出仓库描述、人工摘要和证据链接。旧快照如果含不再符合该策略的全文内容，整体退出公开保留。公共分片同时受每片最多 200 条（默认）和 4 MB 字节上限约束；单条过大时构建失败。独立消费者默认 8 MiB 单片上限，因此不会由合法常规生成器产出其无法读取的超大分片。

ADR-019（浏览器依赖声明）：依据实际浏览器模块图，随完整静态包生成 `third-party-notices.txt`，保留已安装包的精确版本和完整许可/声明文本，包括被打包的构建工具运行时。JavaScript 输出保留声明入口。未归属的虚拟运行时代码或缺失许可文本会阻止构建；这不授予 AIPOCH 原创内容或设计原件许可，见 [依赖声明](third-party-notices.md)。

ADR-020（候选身份）：受信 main 刷新检出触发事件的确切 `github.sha`，不在排队后重新选择可能前移的 main。候选可按根路径或预设 Pages 子路径生成；选择基路径不触发部署。发布必须使用明确审阅的提交、运行尝试、产物摘要与目录快照，不能从文件名推断发布授权。

ADR-021（重跑后的恢复顺序）：恢复器完整读取有界 artifact 清单，以产物实际生成时间选择证据，并逐项核验确切运行尝试；旧 run 的新尝试不能被创建时间排序遗漏。失败尝试只补充负面台账，成功尝试才可恢复正向观察及目录历史。清单缺页或身份无法确认时停止恢复，见 [自动化边界](automation.md)。

ADR-022（v9-r2 前端接纳，实施中）：保留静态预生成和独立目录，在浏览器导航层维持有效会话与完整目录解析。工作台 UI 使用本站独立接口；默认生产 unavailable，明确预览构建提供 Demo 与隔离 Review。此决定不定义正式传输、握手、端口或客户端 schema。范围内 R01–R12 / V01–V18 必须由当前源码、两种模式与根/子路径证据证明，归档和旧测试不能作为新功能通过证明；进度见 [本版实施记录](verification/v9-r2/implementation-status.md)。

ADR-023（独立 Connector 适配）：后续明确授权的 Connector 实施增加显式 `real` 构建，配对和限权会话访问本机 `127.0.0.1:47821`，继续使用网站现有状态机与完整审阅。原始审阅文本是独立 1.0 接收信封的 opaque payload，不扩展公共目录、不导入客户端源码、不添加 GitHub 授权网页。默认 unavailable 与独立 Demo 均保留，实际联调和生产启用分别记录；详见[真实适配说明](connector-adapter.md)。本决定仅替代第 2 节原先排除的“真实网站传输适配”范围；GitHub 权限、客户端项目操作和运行仍由独立 Connector/客户端负责，其他排除范围保持。

ADR-024（Issue #5 连接阶段与显式接续，2026-09-14）：用户已授权实施 [v9-r2 局部修订](../design/changes/issue-5-connection-guidance.md)。Network 使用 Connector 已公开的工作台聊天／MCP 查看待确认请求路径提供逐步说明和可复制来源／比对码，不增加浏览器确认 API、猜测深链或读取 private ticket。连接成功只更新会话状态，不自动进入审阅或重开已关闭面板；原对象与浏览上下文保留，用户明确继续后重新核验准确引用并显式确认发送。关闭面板继续等待与取消网站等待分别说明，真实截止、旧尝试和迟到响应受同一状态守卫。协议 1.0、公共目录、个人库和凭据存储边界保持不变；设计团队签认、实现、四场景真实验收及发布的独立状态见 [本次验收](verification/issue-5/README.md)。


ADR-025（Issue #7 长期浏览器授权，2026-09-14，候选实施）：用户已明确选择长期记住授权，并授权完成 [Network #7](https://github.com/imjszhang/aipoch-network/issues/7) 与 [Connector #5](https://github.com/imjszhang/aipoch-connector/issues/5) 及验收。本决定仅调整原先“全部连接凭据仅内存、刷新后必须重新配对”的限制；短期会话 token 仍只在适配器私有内存，个人操作和引用发送始终需要经过实际验证的当前会话。

- 初次明确连接时，Network 在可用的 IndexedDB 中创建并读回验证不可导出的 P-256 私钥，配对只提交公钥与浏览器显示名称。Connector 本机确认页在请求支持时默认勾选“记住此浏览器”，批准绑定已经捕获的准确来源和公钥；取消记住仍只连接本次访问。该授权不是 GitHub 账号、工作台 daemon 凭据或研究执行许可。
- 长期授权的权威记录由独立 Connector 管理，绑定准确网站 origin、浏览器公钥、本机 Connector 安装身份和稳定工作台身份。正常重启保留授权；另一安装或工作台不能继承。连续 90 天无有效使用失效，成功取得新会话或核验当前有效会话等实际使用可以续期，失败请求和取挑战不能续期。
- 刷新、重开及浏览器重启后，Network 先读取身份，再通过可选 `persistentAuthorization` 1.0 能力、一次性挑战与精确绑定验证恢复新短期会话，最后核验 `/v1/session` 后显示 Connected。协议和引用信封仍是 1.0，公开目录 `catalog/v1` 不变。只有有效身份证明之后的工作台不可用结果可显示“已记住，等待工作台”；Connector 不可达仍是未能核验，不能推断安装状态。
- Disconnect 暂停本 origin 在该浏览器的所有标签页与后续访问自动恢复，直到明确 Connect。IndexedDB 中的身份状态、仅含控制信息的 localStorage 和跨标签通知共同限制恢复；通知本身不授予会话资格。Forget 先取消本页和其他标签的资格、清除持久恢复身份，再以暂存于内存的撤销证明请求 Connector 撤销。离线或回复丢失时只说明本地已清除、远端撤销未确认，并引导 Connector 已授权浏览器管理；不保留可悄悄自动恢复的隐藏长期 token。
- 自动恢复不产生新的配对、不打开引用审阅、不恢复确认勾选，也不发送引用。选中对象和本地收藏可保留；当前会话、审阅资格和等待中请求在暂停／忘记／失效时清空。暂时无法核验采用有限退避与受限焦点重试，避免持续请求。
- 非导出属性只限制 Web Crypto 直接导出私钥；同源恶意脚本仍可能调用签名或盗取当前会话，浏览器配置备份也不等于硬件证明。浏览器不支持可靠持久化、存储受限或旧 Connector 不支持扩展时，明确回退只连接本次访问，不宣称已记住。私密浏览是否保留数据取决于实际浏览器生命周期，不能提前承诺跨浏览器重启。

Network 不读取或复制 Connector 的源码、内部类型、数据库、宿主文件或凭据；按 Connector 仓库候选的版本化契约 `docs/persistent-authorization.md` 与各仓库独立夹具对齐；该新契约尚未发布，公开后需固定为审阅过的提交地址。默认 unavailable 和独立、持续标注的 Demo 保持；只有显式 real 构建使用此扩展。原始 v9-r2 参考不改写，R09/V11 的持久身份例外、设计差异与完整证据见 [设计记录](../design/changes/issue-7-persistent-authorization.md) 和 [Issue #7 验收账本](verification/issue-7/README.md)。本决定不代表实际 Firefox/Chrome/任务内浏览器验收、发布或远端 Issue 关闭已经完成。
